# ONNX Runtime Web

[ONNX Runtime Web](https://onnxruntime.ai/docs/get-started/with-javascript/web.html) 可在浏览器中运行 `.onnx` 模型。它的 WebNN 执行提供程序（EP）会把模型中 WebNN 能够运行的部分交给浏览器的 WebNN 实现，后者可以使用 CPU、GPU 或 NPU。WebNN 无法运行的算子会回退到 WebAssembly CPU EP，因此大多数模型仍然可以运行。

创建 `InferenceSession` 时，通过 `executionProviders: ['webnn']` 选择 WebNN EP。其余部分，例如张量、输入和输出，与 `wasm` EP 的用法相同。

> <InfoIcon /> WebNN API 及其浏览器支持仍在不断演进。请始终保留 `'wasm'` 作为回退，浏览器的设置请参见[安装](../../get-started/installation)。

## 何时选择 ONNX Runtime Web [#when-to-choose]

| | [LiteRT.js](../lite-rt/lite-rt) | ONNX Runtime Web | [Transformers.js](../transformers-js/transformers-js) |
| --- | --- | --- | --- |
| **模型格式** | `.tflite` | `.onnx` | 来自 Hugging Face Hub 的 ONNX 模型 |
| **抽象层级** | 运行模型，前处理和后处理由你编写 | 运行模型，前处理和后处理由你编写 | 任务流水线，已包含前处理和后处理 |
| **WebNN 选项** | `accelerator: 'webnn'` | `executionProviders: ['webnn']` | `device: 'webnn-gpu'` 等 |

如果你拥有 ONNX 模型，并希望直接控制会话、形状和张量，请选择 ONNX Runtime Web。Transformers.js 底层使用 ONNX Runtime Web，因此本页关于形状和 WebNN EP 的内容同样适用于它。

## WebNN EP 的工作原理 [#how-it-works]

使用 `webnn` EP 创建会话时：

1. ONNX Runtime Web 使用你指定的 `deviceType` 和 `powerPreference`，通过 `navigator.ml.createContext()` 创建 [`MLContext`](../../../api-reference/webnn/mlcontext)。
2. EP 读取该上下文的算子和数据类型限制，并标记它能够构建的节点。
3. 模型图被划分为多个分区。每个由受支持节点组成的分区会被编译为一个 WebNN 图，其余节点保留在 Wasm CPU EP 上。
4. 每次调用 `run()` 时，各分区通过 WebNN 执行，其余节点在 Wasm 上执行。

WebNN 与 Wasm 之间的每次切换都有开销。被划分为许多分区的模型，运行速度可能比只使用 `wasm` 更慢，因此请检查分区数量，参见[验证是否使用了 WebNN](#verify)。

## 前提条件 [#prerequisites]

- 已启用 WebNN 的浏览器。请按照[安装](../../get-started/installation)操作。
- [安全上下文](https://developer.mozilla.org/zh-CN/docs/Web/Security/Secure_Contexts)：HTTPS 或 `localhost`。
- 一个 `.onnx` 模型，最好具有固定的输入形状，参见[固定形状](#static-shapes)。

## 安装 [#install]

```bash showLineNumbers filename="terminal"
npm install onnxruntime-web
```

该包在 `package.json` 的 exports 中提供了多个入口。对于 WebNN，ONNX Runtime 文档使用 `onnxruntime-web/all`，同时还提供 JSPI 构建版本 `onnxruntime-web/jspi`。

| 导入 | 用途 |
| --- | --- |
| `onnxruntime-web/all` | [ONNX Runtime WebNN 指南](https://onnxruntime.ai/docs/tutorials/web/ep-webnn.html)所使用的包。建议从这里开始。 |
| `onnxruntime-web/jspi` | JSPI 构建版本，会加载 `ort-wasm-simd-threaded.jspi.wasm`。需要支持 WebAssembly JSPI 的浏览器。 |

使用 script 标签时，请加载 `ort.all.min.js`，而不是 `ort.min.js`：

```html showLineNumbers filename="index.html"
<script src="https://cdn.jsdelivr.net/npm/onnxruntime-web/dist/ort.all.min.js"></script>
```

> <InfoIcon /> 在生产环境中请固定版本，例如 `onnxruntime-web@<version>`，并使用你测试过的确切版本，以确保 JavaScript 包与 Wasm 文件始终匹配。每夜构建版 `onnxruntime-web@dev` 可能包含更新的 WebNN 修复。

## 使用 WebNN EP [#use-webnn]

<Steps>

### 导入 ONNX Runtime Web [#step-import]

```js showLineNumbers filename="session.js"
import * as ort from 'onnxruntime-web/all';
```

如果 Wasm 文件没有与你的包放在同一位置，请让 ONNX Runtime Web 指向它们。`env.wasm.wasmPaths` 接受一个 URL 前缀，或者带有 `wasm` 和 `mjs` 覆盖项的对象。

```js showLineNumbers filename="env.js"
ort.env.wasm.wasmPaths = '/ort/';
```

### 创建会话 [#step-session]

```js showLineNumbers filename="session.js"
const session = await ort.InferenceSession.create('/models/mobilenetv2-12.onnx', {
  executionProviders: [
    { name: 'webnn', deviceType: 'gpu', powerPreference: 'default' },
    'wasm',
  ],
  // 键必须与模型中存储的自由维度名称一致。
  freeDimensionOverrides: { batch_size: 1 },
});

console.log('Inputs:', session.inputNames, 'Outputs:', session.outputNames);
```

`create()` 接受 URL 或模型字节的 `Uint8Array`。EP 会按顺序尝试，因此放在 `webnn` 之后的 `'wasm'` 是保底方案。选项详情参见[执行提供程序选项](#options)。

### 运行推理 [#step-run]

用类型化数组和形状创建 `ort.Tensor`，并按输入名称传入。

```js showLineNumbers filename="run.js"
const data = new Float32Array(1 * 3 * 224 * 224);
const input = new ort.Tensor('float32', data, [1, 3, 224, 224]);

const results = await session.run({ [session.inputNames[0]]: input });
const scores = results[session.outputNames[0]].data; // 一个 Float32Array
console.log('Number of scores:', scores.length);
```

### 释放会话 [#step-release]

```js showLineNumbers filename="release.js"
await session.release();
```

</Steps>

## 执行提供程序选项 [#options]

这些是 ONNX Runtime Web 的选项，在 `executionProviders` 的 `webnn` 条目中传入。它们与 WebNN API 的 [`MLContextOptions`](../../../api-reference/webnn/ml#createcontext) 不同，后者已不再包含 `deviceType`。ONNX Runtime Web 使用 `deviceType` 来配置图构建器并请求上下文。

| 选项 | 取值 | 描述 |
| --- | --- | --- |
| `deviceType` | `'cpu'`, `'gpu'`, `'npu'` | 上下文应当面向的设备。对于其他任何字符串，WebNN EP 都会抛出 `Unknown WebNN deviceType.`。 |
| `powerPreference` | `'default'`, `'low-power'`, `'high-performance'` | 对功耗与性能权衡的提示。 |
| `context` | 一个 `MLContext` | 使用你自己创建的上下文。此时 `deviceType` 为必填项，以便 EP 选择首选布局。 |
| `gpuDevice` | 一个 `GPUDevice` | 使用此 WebGPU 设备创建 `MLContext`。 |

字符串形式 `'webnn'` 使用默认选项创建上下文。`numThreads` 也出现在选项类型中，但源码中的会话代码并未使用它，因此请不要依赖它。

> <InfoIcon /> 这些只是提示。最终的设备选择由浏览器决定，可能与你的偏好不同。参见[设备选择示意图](../../../api-reference/browser-compatibility/deviceselection)。

还有两个会话选项对 WebNN 也很重要：

| 会话选项 | 描述 |
| --- | --- |
| `freeDimensionOverrides` | 将命名的自由维度固定为具体数字。参见[固定形状](#static-shapes)。 |
| `preferredOutputLocation` | `run()` 之后输出保留的位置，例如 `'ml-tensor'`。参见 [MLTensor 与 IO 绑定](#mltensor)。 |

## 固定形状 [#static-shapes]

WebNN 使用固定的张量形状编译图。如果某个节点的张量带有自由维度，WebNN EP 会拒绝该节点，并在 verbose 级别记录 `Dynamic shape is not supported, use sessionOptions.FreeDimensionOverrides to set a fixed shape`。该节点，通常还有图的大部分，随后会在 Wasm 上运行。

解决方法是用 `freeDimensionOverrides` 为每个自由维度指定一个数字。键是 ONNX 模型中存储的维度名称，例如 `batch_size`：

```js showLineNumbers filename="static-shapes.js"
const session = await ort.InferenceSession.create(modelUrl, {
  executionProviders: ['webnn'],
  freeDimensionOverrides: { batch_size: 1, sequence_length: 128 },
});
```

可以使用 [Netron](https://netron.app) 之类的查看器查找模型中的维度名称。完整的演练请参见[自由维度覆盖](./free-dimension-overrides)；如果模型比预期更慢，请参见[性能问题](../../troubleshooting/performance-issues)。

## 完整示例：图像分类 [#image-classification]

此示例使用一个 ONNX MobileNet 对图像分类，其输入为 `float32` 类型的 `[1, 3, 224, 224]`，并使用 ImageNet 的均值和标准差进行归一化。它先尝试在 GPU 上使用 WebNN，再尝试 NPU，最后回退到 Wasm。请根据你的模型调整模型 URL、尺寸和归一化方式。

```js showLineNumbers filename="classify.js"
import * as ort from 'onnxruntime-web/all';

const SIZE = 224;
const MEAN = [0.485, 0.456, 0.406];
const STD = [0.229, 0.224, 0.225];

ort.env.wasm.wasmPaths = '/ort/';

// 依次尝试每个执行提供程序列表，直到能够创建会话。
export async function createSession(modelUrl) {
  const bytes = new Uint8Array(await (await fetch(modelUrl)).arrayBuffer());
  const candidates = [
    [{ name: 'webnn', deviceType: 'gpu' }],
    [{ name: 'webnn', deviceType: 'npu' }],
    ['wasm'],
  ];

  for (const executionProviders of candidates) {
    try {
      const session = await ort.InferenceSession.create(bytes, {
        executionProviders,
        freeDimensionOverrides: { batch_size: 1 },
      });
      console.log('Session created with', JSON.stringify(executionProviders));
      return session;
    } catch (error) {
      console.warn('Could not use', JSON.stringify(executionProviders), error);
    }
  }
  throw new Error('No execution provider could create a session.');
}

// 将图像（HTMLImageElement、ImageBitmap、canvas）转换为归一化的 NCHW 张量。
function preprocess(image) {
  const canvas = new OffscreenCanvas(SIZE, SIZE);
  const context = canvas.getContext('2d', { willReadFrequently: true });
  context.drawImage(image, 0, 0, SIZE, SIZE);
  const { data } = context.getImageData(0, 0, SIZE, SIZE); // RGBA，逐行排列

  const chw = new Float32Array(3 * SIZE * SIZE);
  for (let i = 0; i < SIZE * SIZE; i++) {
    for (let channel = 0; channel < 3; channel++) {
      chw[channel * SIZE * SIZE + i] = (data[i * 4 + channel] / 255 - MEAN[channel]) / STD[channel];
    }
  }
  return new ort.Tensor('float32', chw, [1, 3, SIZE, SIZE]);
}

// 对原始分数做 softmax，然后返回概率最高的 k 个标签。
function topK(scores, labels, k = 5) {
  const max = Math.max(...scores);
  const exps = Array.from(scores, (score) => Math.exp(score - max));
  const sum = exps.reduce((a, b) => a + b, 0);
  return exps
    .map((value, index) => ({ label: labels[index], probability: value / sum }))
    .sort((a, b) => b.probability - a.probability)
    .slice(0, k);
}

export async function classify(session, image, labels) {
  const input = preprocess(image);
  const results = await session.run({ [session.inputNames[0]]: input });
  return topK(results[session.outputNames[0]].data, labels);
}
```

```js showLineNumbers filename="main.js"
import { createSession, classify } from './classify.js';

const labels = await (await fetch('/models/imagenet_labels.json')).json();
const session = await createSession('/models/mobilenetv2-12.onnx');

const image = document.querySelector('img');
console.table(await classify(session, image, labels));
```

完整的演练，包括页面设置，请参见[图像分类](./image-classification)。

## 回退行为 [#fallback]

回退分为两个层级：

- **按算子。** WebNN 无法构建的节点，例如在此设备上不受支持的算子、数据类型或形状，会在 Wasm CPU EP 上运行。会话仍会创建成功。
- **按会话。** 如果 `InferenceSession.create()` 抛出异常，例如 WebNN 不可用，请使用 `executionProviders: ['wasm']` 重试，如上面的示例所示。

量化模型会被特殊处理：使用 `webnn` EP 时，ONNX Runtime Web 会关闭 QDQ 融合和 QDQ 常量折叠，因此 `DequantizeLinear` 和 `QuantizeLinear` 节点会作为单独的算子到达 WebNN EP。

## MLTensor 与 IO 绑定 [#mltensor]

默认情况下，输入和输出位于 CPU 内存中，使用 `gpu` 或 `npu` 时，每次运行都会把数据复制到设备再复制回来。借助 [`MLTensor`](../../../api-reference/webnn/mltensor)，数据可以保留在设备上。当输出被回馈为输入时，例如 transformer 的解码循环，这一点最有帮助。源码确认存在 `ort.Tensor.fromMLTensor()` 和 `'ml-tensor'` 输出位置。

根据 ONNX Runtime 指南，IO 绑定需要一个共享的 `MLContext`，它需要预先创建，并与 `deviceType` 一起作为 EP 的 `context` 选项传入。

```js showLineNumbers filename="io-binding.js"
// ONNX Runtime Web 仍然需要在 context 旁边提供 deviceType。
const deviceType = 'gpu';
const mlContext = await navigator.ml.createContext({ powerPreference: 'high-performance' });

const session = await ort.InferenceSession.create(modelUrl, {
  executionProviders: [{ name: 'webnn', context: mlContext, deviceType }],
  freeDimensionOverrides: { batch_size: 1 },
  preferredOutputLocation: 'ml-tensor',
});

// 一个已经位于 MLTensor 上的输入
const mlTensor = await mlContext.createTensor({
  dataType: 'float32',
  shape: [1, 3, 224, 224],
  writable: true,
});
mlContext.writeTensor(mlTensor, new Float32Array(1 * 3 * 224 * 224));
const input = ort.Tensor.fromMLTensor(mlTensor, { dataType: 'float32', dims: [1, 3, 224, 224] });

const results = await session.run({ [session.inputNames[0]]: input });
const output = results[session.outputNames[0]];
const values = await output.getData(); // 从 MLTensor 下载到 CPU
console.log('Number of values:', values.length);

output.dispose(); // 这个 MLTensor 由 ONNX Runtime 创建，因此需要释放它
mlTensor.destroy(); // 这个由你创建，因此由你销毁
```

`preferredOutputLocation` 也接受以输出名称为键的对象，例如 `{ output_0: 'cpu', output_1: 'ml-tensor' }`。

- 由 `Tensor.fromMLTensor()` 得到的张量归你所有。请在 `run()` 期间保持其有效，并在用完后销毁该 `MLTensor`。使用已销毁的 `MLTensor` 运行会失败。
- ONNX Runtime 创建的输出拥有它自己的 `MLTensor`。请用 `getData()` 读取，并用 `dispose()` 释放。
- WebNN 的 `MLTensor` 部分仍在变化，因此如果此路径失败，请检查你的浏览器版本。

## 常用的 ort.env 标志 [#env-flags]

请在创建第一个会话之前设置这些标志。它们定义在 ONNX Runtime Web 的 `env` 类型中。

| 标志 | 描述 |
| --- | --- |
| `env.wasm.wasmPaths` | Wasm 运行时文件的 URL 前缀，或带有 `wasm` 和 `mjs` 路径的对象。 |
| `env.wasm.numThreads` | Wasm 运行时的线程数。`0` 或未设置时由系统决定，`1` 则不会创建工作线程。 |
| `env.wasm.proxy` | 在工作线程中运行 Wasm 运行时。默认为 `false`。 |
| `env.wasm.simd` | 控制 SIMD 特性检测。默认为 `true`。 |
| `env.wasm.initTimeout` | 运行时初始化的超时时间，单位为毫秒。默认为 `0`，即不设超时。 |
| `env.logLevel` | `'verbose'`、`'info'`、`'warning'`、`'error'` 或 `'fatal'`。 |

> <InfoIcon /> `numThreads` 和 `proxy` 用于配置 Wasm 运行时和回退节点，不会改变在 WebNN 上运行的内容。位于 `'ml-tensor'` 位置的张量无法跨代理 Worker 序列化，因此请避免将 `env.wasm.proxy` 与 IO 绑定结合使用。

## 在 Web Worker 中运行 [#web-worker]

在 Worker 中运行推理，可以让会话的创建和执行不占用主线程。[Web AI Run](https://github.com/ibelem/web-ai-run) 的推理 Worker 使用 ONNX Runtime Web 配合 WebNN 运行，采用的就是这种模式：

- 它是经典（classic）Worker，而不是模块（module）Worker，因为 Wasm 加载器会调用 `importScripts()`，而模块 Worker 没有该函数。
- 它通过动态 `import()` 加载 JSPI 包 `ort.jspi.min.mjs`，然后把 `ort.env.wasm.wasmPaths` 设置为存放 Wasm 文件的文件夹。

```js showLineNumbers filename="inference-worker.js"
// 在生产环境中请固定确切的版本，而不是使用 'latest'。
const BASE = 'https://cdn.jsdelivr.net/npm/onnxruntime-web@latest/dist/';
let session;

self.onmessage = async (event) => {
  if (event.data.type === 'init') {
    const ort = await import(BASE + 'ort.jspi.min.mjs');
    ort.env.wasm.wasmPaths = BASE;

    session = await ort.InferenceSession.create(event.data.modelUrl, {
      executionProviders: [{ name: 'webnn', deviceType: 'gpu' }, 'wasm'],
      freeDimensionOverrides: event.data.freeDimensionOverrides,
    });
    self.postMessage({ type: 'ready' });
  }
};
```

请把 `latest` 替换为你所使用的确切版本，并使用 `new Worker('/inference-worker.js')` 创建 Worker，不要加 `{ type: 'module' }`。

## 验证是否使用了 WebNN [#verify]

成功创建的会话并不一定运行在你的 GPU 或 NPU 上。可以这样检查：

1. 在创建会话之前设置 `ort.env.logLevel = 'verbose'`。
2. 找到 WebNN EP 输出的这一行：`WebNNExecutionProvider::GetCapability, number of partitions supported by WebNN: ... number of nodes in the graph: ... number of nodes supported by WebNN: ...`。如果只有一个分区且覆盖了几乎所有节点，说明模型几乎完全在 WebNN 上运行。当分区多于一个时，EP 会以警告级别写出这一行，否则以信息级别写出。
3. 查找关于不受支持的形状或数据类型的 verbose 消息，例如上文的动态形状消息。

要确认硬件正在工作，请使用[调试](../../get-started/debug)中介绍的浏览器和操作系统工具。

## 支持的算子和数据类型 [#supported-ops]

WebNN EP 使用 [`onnxruntime/core/providers/webnn/builders`](https://github.com/microsoft/onnxruntime/tree/main/onnxruntime/core/providers/webnn/builders) 中的构建器来构建 ONNX 算子。支持情况还取决于浏览器，因为 EP 会在运行时从上下文中读取所支持的数据类型和限制。持续维护的算子列表见 [webnn-operators.md](https://github.com/microsoft/onnxruntime/blob/main/js/web/docs/webnn-operators.md)。

## 故障排除 [#troubleshooting]

| 现象 | 原因与解决方法 |
| --- | --- |
| `WebNN is not supported in current environment` | 缺少 `navigator.ml`。请启用 WebNN 并使用安全上下文，参见[安装](../../get-started/installation)。 |
| `Failed to create WebNN context.` | EP 没有可用的 `MLContext`。请尝试其他 `deviceType`，或参见[硬件错误](../../troubleshooting/hardware-errors)。 |
| `Unknown WebNN deviceType.` | `deviceType` 必须是 `'cpu'`、`'gpu'` 或 `'npu'`。 |
| `WebAssembly JSPI is not supported in the current environment.` | 你在不支持 JSPI 的浏览器中使用了 JSPI 构建版本。请使用 `onnxruntime-web/all`，或使用支持 JSPI 的浏览器。 |
| Verbose 日志：`Dynamic shape is not supported` | 模型带有自由维度。请设置 `freeDimensionOverrides`，参见[固定形状](#static-shapes)。 |
| 分区很多，推理很慢 | 不受支持的算子把图拆开了。请检查受支持的节点数量，修改模型，或与 `wasm` 对比。 |
| `Tensor location "ml-tensor" is not supported without using WebNN.` | 你在没有 `webnn` EP 的情况下使用了 `MLTensor` 输入或 `preferredOutputLocation: 'ml-tensor'`。 |
| Wasm 文件加载失败 | 请设置 `env.wasm.wasmPaths`，并以正确的 MIME 类型提供这些文件。 |

更多内容请参见[常见错误](../../troubleshooting/common-errors)、[框架错误](../../troubleshooting/framework-errors)和[后端错误](../../troubleshooting/backend-errors)。

## 限制 [#limitations]

- WebNN 要求形状为固定形状。带有动态形状的模型需要 `freeDimensionOverrides`。
- 算子和数据类型的支持取决于浏览器和设备。不受支持的节点会在 Wasm 上运行。
- ONNX Runtime Web 只负责运行模型，前处理和后处理由你的代码完成。
- 并非所有浏览器都已支持 WebNN 和 `MLTensor`。
