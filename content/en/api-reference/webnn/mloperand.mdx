# MLOperand

> <InfoIcon /> **Experimental:** This is an [experimental technology](../browser-compatibility/api#webnn-apis). Check the browser compatibility table carefully before using it in production.

The **`MLOperand`** interface of the Web Neural Network (WebNN) API represents a node in a computational graph that is being built: a graph input, a constant, or the output of an operation. Operands are symbolic — they describe the data type and shape of a value, but hold no data that script can read.

`MLOperand` objects are created by the methods of [`MLGraphBuilder`](mlgraphbuilder), such as [`input()`](mlgraphbuilder#input), [`constant()`](mlgraphbuilder#constant), and every [operation](mlgraphbuilder-ops) like `add()` or `conv2d()`. An operand belongs to the builder that created it, and therefore to that builder's [`MLContext`](mlcontext); passing it to a different builder throws a `TypeError`.

This feature is available only in [secure contexts](https://developer.mozilla.org/docs/Web/Security/Secure_Contexts) (HTTPS or `localhost`), and is available in both the main thread and [Web Workers](https://developer.mozilla.org/docs/Web/API/Web_Workers_API).

## Web IDL [#web-idl]

```webidl showLineNumbers filename="web-idl"
[SecureContext, Exposed=(Window, Worker)]
interface MLOperand {
  readonly attribute MLOperandDataType dataType;
  readonly attribute FrozenArray<unsigned long> shape;
};

dictionary MLOperatorOptions {
  USVString label = "";
};

typedef (bigint or unrestricted double) MLNumber;
```

## Constructor [#constructor]

None. Operands are created by [`MLGraphBuilder`](mlgraphbuilder) methods.

## Instance properties [#instance-properties]

### dataType [#datatype]

A read-only [`MLOperandDataType`](#mloperanddatatype) string giving the operand's element type, for example `"float32"`.

### shape [#shape]

A read-only, frozen array of `unsigned long` values giving the size of each dimension. The number of entries is the operand's **rank**. The array is empty (`[]`) for a scalar.

Because operation outputs have their shapes computed at graph-construction time, you can inspect `shape` to check intermediate results while building:

```js showLineNumbers filename="shape.js"
const x = builder.input('x', { dataType: 'float32', shape: [1, 3, 224, 224] });
const y = builder.averagePool2d(x, { windowDimensions: [2, 2], strides: [2, 2] });
console.log(y.dataType, y.shape); // "float32" [1, 3, 112, 112]
```

## Instance methods [#instance-methods]

None.

## MLOperandDescriptor [#mloperanddescriptor]

The **`MLOperandDescriptor`** dictionary describes the data type and shape of an operand. It is passed to [`MLGraphBuilder.input()`](mlgraphbuilder#input), [`MLGraphBuilder.constant()`](mlgraphbuilder#constant) and [`MLContext.createConstantTensor()`](mlcontext#createconstanttensor), and is the base of [`MLTensorDescriptor`](mltensor#mltensordescriptor).

```webidl showLineNumbers filename="web-idl"
enum MLInputOperandLayout {
  "nchw",
  "nhwc"
};

enum MLOperandDataType {
  "float32",
  "float16",
  "int32",
  "uint32",
  "int64",
  "uint64",
  "int8",
  "uint8"
};

dictionary MLOperandDescriptor {
  required MLOperandDataType dataType;
  required sequence<[EnforceRange] unsigned long> shape;
};
```

| Member | Type | Description |
| --- | --- | --- |
| `dataType` _(required)_ | [`MLOperandDataType`](#mloperanddatatype) | The operand data type. |
| `shape` _(required)_ | `sequence<unsigned long>` | The list of dimensions. Empty for a scalar. |

Each dimension must be an integer greater than zero (zero-sized dimensions are not currently allowed) and within the range of a 32-bit signed integer. The total number of elements must also be in that range, and the total byte length must not exceed the implementation's limit (see [`MLOpSupportLimits.maxTensorByteLength`](mlcontext#mlopsupportlimits)). Otherwise, the method receiving the descriptor throws a `TypeError`.

The **byte length** of a descriptor is the product of all dimensions multiplied by the element size of the data type.

### MLOperandDataType [#mloperanddatatype]

| Value | Description | Element size | Matching `ArrayBufferView` |
| --- | --- | --- | --- |
| `"float32"` | 32-bit IEEE 754 floating point | 4 bytes | `Float32Array` |
| `"float16"` | 16-bit IEEE 754 floating point | 2 bytes | `Float16Array` |
| `"int32"` | 32-bit signed integer | 4 bytes | `Int32Array` |
| `"uint32"` | 32-bit unsigned integer | 4 bytes | `Uint32Array` |
| `"int64"` | 64-bit signed integer | 8 bytes | `BigInt64Array` |
| `"uint64"` | 64-bit unsigned integer | 8 bytes | `BigUint64Array` |
| `"int8"` | 8-bit signed integer | 1 byte | `Int8Array` |
| `"uint8"` | 8-bit unsigned integer; also used for boolean results of logical operations | 1 byte | `Uint8Array` |

Not every operator supports every data type on every platform. Each operator lists its _allowed_ and _required_ data types; use [`MLContext.opSupportLimits()`](mlcontext#opsupportlimits) to query what the current context supports.

### MLInputOperandLayout [#mlinputoperandlayout]

The memory layout of 4-D image-like tensors, used by layout-dependent operators such as `conv2d()`, `convTranspose2d()`, pooling, `instanceNormalization()` and `resample2d()`.

| Value | Description |
| --- | --- |
| `"nchw"` | `[batches, channels, height, width]` (channels-first) |
| `"nhwc"` | `[batches, height, width, channels]` (channels-last) |

The layout that the current platform prefers is reported by [`MLOpSupportLimits.preferredInputLayout`](mlcontext#mlopsupportlimits).

## MLOperatorOptions [#mloperatoroptions]

The **`MLOperatorOptions`** dictionary is the base of every operation's options dictionary. Every [operation](mlgraphbuilder-ops) accepts it, either directly or through a derived dictionary such as `MLConv2dOptions`.

| Member | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `USVString` | `""` | An identifier for the operator. Implementations may use it in error messages and debugging tools, both for synchronous errors during graph construction and for errors reported by `build()`. |

The label is not intended to be a natural-language string; treat it like a variable name or error code, for example `"mul#1234"` or `"encoder.layer3.attention.matmul"`.

```js showLineNumbers filename="label.js"
try {
  builder.matmul(a, b, { label: 'decoder.proj' });
} catch (e) {
  console.error(e.message); // The message may mention "decoder.proj".
}
```

## MLNumber [#mlnumber]

**`MLNumber`** is a union of `bigint` and `unrestricted double`, used for numeric options whose type depends on an operand's data type — for example `minValue`/`maxValue` of [`clamp()`](mlgraphbuilder-ops#clamp), `value` of [`pad()`](mlgraphbuilder-ops#pad), and the scalar [`constant(dataType, value)`](mlgraphbuilder#constant) overload.

A `double` alone would lose precision for 64-bit integers above 2<sup>53</sup>, and a `long long` could not hold values above 2<sup>63</sup>. The implementation casts the `MLNumber` to the relevant operand data type:

- For integer types, the value is converted to that integer type; use a `bigint` (for example `2n ** 60n`) to keep full 64-bit precision.
- For floating-point types, the value is converted to the nearest representable value.
- Values outside the range of the target type are truncated.

```js showLineNumbers filename="mlnumber.js"
const big = builder.constant('int64', 9007199254740993n); // Exact, beyond 2^53.
const clamped = builder.clamp(x, { minValue: 0, maxValue: 6 }); // Cast to x.dataType.
```

## Examples [#examples]

### Inspecting operands while building a graph [#inspecting-operands-while-building-a-graph]

```js showLineNumbers filename="operands.js"
const context = await navigator.ml.createContext();
const builder = new MLGraphBuilder(context);

const input = builder.input('input', { dataType: 'float32', shape: [1, 4] });
const weights = builder.constant(
  { dataType: 'float32', shape: [4, 2] },
  new Float32Array([1, 0, 0, 1, 1, 0, 0, 1]),
);
const scalar = builder.constant('float32', 0.5);

const product = builder.matmul(input, weights);
const output = builder.mul(product, scalar);

console.log(product.shape); // [1, 2]
console.log(scalar.shape);  // [] (scalar)
console.log(output.dataType); // "float32"
```
