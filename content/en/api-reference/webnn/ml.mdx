# ML

> <InfoIcon /> **Experimental:** This is an [experimental technology](../browser-compatibility/api#webnn-apis). Check the browser compatibility table carefully before using it in production.

The **`ML`** interface of the Web Neural Network (WebNN) API is the entry point for creating [`MLContext`](mlcontext) objects. An `ML` object is obtained through the [`navigator.ml`](navigatorml) property.

This feature is available only in [secure contexts](https://developer.mozilla.org/docs/Web/Security/Secure_Contexts) (HTTPS or `localhost`), and is available in both the main thread and [Web Workers](https://developer.mozilla.org/docs/Web/API/Web_Workers_API).

## Web IDL [#web-idl]

```webidl showLineNumbers filename="web-idl"
enum MLPowerPreference {
  "default",
  "high-performance",
  "low-power"
};

dictionary MLContextOptions {
  MLPowerPreference powerPreference = "default";
  boolean accelerated = true;
};

[SecureContext, Exposed=(Window, Worker)]
interface ML {
  Promise<MLContext> createContext(optional MLContextOptions options = {});
  Promise<MLContext> createContext(GPUDevice gpuDevice);
};
```

## Instance properties [#instance-properties]

None.

## Instance methods [#instance-methods]

| Method | Description |
| --- | --- |
| [`createContext()`](#createcontext) | Returns a `Promise` that resolves to a new [`MLContext`](mlcontext), configured either from an `MLContextOptions` dictionary or from a WebGPU [`GPUDevice`](https://developer.mozilla.org/docs/Web/API/GPUDevice). |

### createContext() [#createcontext]

The **`createContext()`** method of the `ML` interface creates an [`MLContext`](mlcontext), which holds the global state for graph compilation and execution.

#### Syntax [#createcontext-syntax]

```js showLineNumbers filename="syntax.js"
createContext()
createContext(options)
createContext(gpuDevice)
```

#### Parameters [#createcontext-parameters]

- `options` _optional_

  An [`MLContextOptions`](#mlcontextoptions) dictionary describing the application's preferences for the context. The resulting context has the context type `"default"`.
- `gpuDevice`

  A WebGPU [`GPUDevice`](https://developer.mozilla.org/docs/Web/API/GPUDevice). The resulting context has the context type `"webgpu"` and is associated with that device, which enables interoperability between WebNN and WebGPU. A context created this way uses a `powerPreference` of `"default"` and an `accelerated` value of `true`.

#### Return value [#createcontext-return-value]

A [`Promise`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Promise) that fulfills with an [`MLContext`](mlcontext) object.

#### Exceptions [#createcontext-exceptions]

The returned promise is rejected with:

- `SecurityError` [`DOMException`](https://developer.mozilla.org/docs/Web/API/DOMException)

  The document is not allowed to use the `webnn` [Permissions Policy](navigatorml#permissions-policy) feature.
- `NotSupportedError` [`DOMException`](https://developer.mozilla.org/docs/Web/API/DOMException)

  The user agent cannot create a context of the requested type (for example, the platform has no usable backend, or WebGPU interop is not supported).

## Dictionaries and enumerations [#dictionaries-and-enumerations]

### MLContextOptions [#mlcontextoptions]

A dictionary of hints that the user agent uses to select the underlying compute device and execution mode. These are **preferences**, not requirements: the implementation chooses the best available match on the current platform.

| Member | Type | Default | Description |
| --- | --- | --- | --- |
| `powerPreference` | [`MLPowerPreference`](#mlpowerpreference) | `"default"` | The application's preference related to power consumption. |
| `accelerated` | `boolean` | `true` | The application's preference for massively parallel acceleration. When `true`, the platform attempts to use an available accelerator such as a GPU or NPU (also taking `powerPreference` into account). When `false`, the application indicates that it prefers CPU inference. |

`accelerated` has lower priority than `powerPreference`. If the two contradict each other (for example `powerPreference: "high-performance"` together with `accelerated: false`), the implementation picks the best available match, for instance a high-performance CPU mode, or ignores `accelerated`.

Whether a context is actually accelerated can be checked afterwards with the [`MLContext.accelerated`](mlcontext#accelerated) property.

> <InfoIcon /> `MLContextOptions` is under active development and its design may change. The Working Group is considering controls for fallback devices, an ordered list of preferred devices, excluding specific devices, error handling, and quantized operators. See the [device selection explainer](https://github.com/webmachinelearning/webnn/blob/main/device-selection-explainer.md) for background.

### MLPowerPreference [#mlpowerpreference]

| Value | Description |
| --- | --- |
| `"default"` | Lets the user agent select the most suitable behavior. |
| `"high-performance"` | Prioritizes execution speed over power consumption. |
| `"low-power"` | Prioritizes power consumption over other considerations such as execution speed. |

### Migrating from `deviceType` [#migrating-from-devicetype]

Earlier drafts of the specification defined an `MLDeviceType` enum and a `deviceType` member (`"cpu"`, `"gpu"`, `"npu"`) on `MLContextOptions`. These have been **removed** from the specification to make contexts device-agnostic by default. The following hints express similar intent, but the final device choice is always made by the implementation (for example, an NPU may be faster than the GPU on some devices):

| Earlier code | Closest current hint |
| --- | --- |
| `{ deviceType: 'cpu' }` | `{ accelerated: false }` |
| `{ deviceType: 'gpu' }` | `{ powerPreference: 'high-performance' }` (or pass a `GPUDevice` to share work with WebGPU) |
| `{ deviceType: 'npu' }` | `{ powerPreference: 'low-power' }` |

> <InfoIcon /> Some browsers may still accept `deviceType` for compatibility while the API is in development. New code should rely on `powerPreference` and `accelerated` only. See [Browser Compatibility: Device Selection](../browser-compatibility/deviceselection).

## Examples [#examples]

### Creating a context with default options [#creating-a-context-with-default-options]

```js showLineNumbers filename="default-context.js"
try {
  const context = await navigator.ml.createContext();
  console.log('Accelerated:', context.accelerated);
} catch (error) {
  console.error(`Failed to create an MLContext: ${error.name}: ${error.message}`);
}
```

### Requesting a power preference [#requesting-a-power-preference]

```js showLineNumbers filename="power-preference.js"
// Favor battery life, e.g. for an always-on background-blur effect.
const lowPowerContext = await navigator.ml.createContext({
  powerPreference: 'low-power',
});

// Favor throughput, e.g. for interactive image generation.
const fastContext = await navigator.ml.createContext({
  powerPreference: 'high-performance',
});
```

### Preferring CPU inference [#preferring-cpu-inference]

```js showLineNumbers filename="cpu-context.js"
const context = await navigator.ml.createContext({ accelerated: false });
console.log(context.accelerated); // usually false
```

### Creating a context from a WebGPU device [#creating-a-context-from-a-webgpu-device]

```js showLineNumbers filename="webgpu-context.js"
const adapter = await navigator.gpu.requestAdapter();
const gpuDevice = await adapter.requestDevice();

try {
  const context = await navigator.ml.createContext(gpuDevice);
  // Tensors created with context.createExportableTensor(descriptor, gpuDevice)
  // can be shared with WebGPU via context.exportToGPU(tensor).
} catch (error) {
  console.error('WebNN/WebGPU interop is not available:', error);
}
```
